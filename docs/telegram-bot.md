# بوت المخزون على تليجرام

بوت **للأدمن وحدهم**، منفصل عن متجر الزبائن. فكرته سطر واحد:

> البائع يطلب بطاقة → البوت يحجزها ويعطيه الكود → **تأكيد** إن نجحت
> العملية، **إلغاء** إن فشلت فترجع البطاقة إلى المخزون.

وكل عملية ناجحة تُحسب لصاحبها، فيعرف المالك في أي لحظة من باع كم.

---

## 1. كيف يبدو الاستعمال

جاء زبون يريد اشتراك سنة:

1. يفتح البائع البوت ويضغط **🛒 بيع بطاقة**
2. يختار المنتج، ثم المدة — والزر نفسه يقول كم بقي: «سنة — 12 متاحة»
3. يصله الكود في رسالة، ومعه زرّان:

   * **📋 نسخ الكود** — زر نسخ حقيقي: ضغطة واحدة والكود في الحافظة،
     بلا تحديد يدوي. (الكود نفسه فوقه داخل إطار، والنقر عليه ينسخ
     أيضاً على العملاء الأقدم.)
   * **✅ تأكيد** — سلّمه للزبون وقبض. البطاقة تصبح مباعة نهائياً،
     وعدّاد البائع يزيد واحداً.
   * **❌ إلغاء** — لم تتم. البطاقة ترجع إلى المخزون فوراً ليأخذها
     زبون آخر، والكود يُمحى من الرسالة، ولا شيء يُحسب للبائع.

بعد التأكيد تقول الرسالة **ماذا بيع بالضبط** — المنتج والمدة، لا الكود
وحده — وكم باع البائع من تلك المدة تحديداً:

```
✅ عملية ناجحة

🎟 نتفليكس — سنة
ABCD-1234-EFGH

بعت من «سنة»: 8
إجمالي مبيعاتك: 12
المتبقي في المخزون: 4
```

البطاقة **محجوزة** بين الطلب والتأكيد: لا يمكن أن تخرج لبائع آخر في
تلك الأثناء، حتى لو ضغط الاثنان في نفس الثانية.

---

## 2. الأزرار

| الزر | لمن | ماذا يفعل |
|---|---|---|
| 🛒 بيع بطاقة | الجميع | المنتج ← المدة ← الكود + زرّا تأكيد/إلغاء |
| ⏳ المعلّقة | الجميع | ما لم يُبتّ فيه بعد، وتُغلق من نفس القائمة |
| 📊 مبيعاتي | الجميع | الناجحة، اليوم، هذا الشهر، الملغاة — **ومفصّلة: كم سنة وكم 3 أشهر** |
| 📦 المخزون | المالك | كل منتج ومدّة: متاحة / محجوزة / مباعة |
| 🏆 مبيعات الكل | المالك | ترتيب البائعين، وتحت كل واحد ماذا باع بالتفصيل |
| ➕ شحن أكواد | المالك | يسأل عن المدة ثم تردّ عليه بالأكواد |
| 👥 الأدمن | المالك | من يدخل البوت — واضغط على أي واحد لترى ماذا باع وكم من كل مدة |
| ⏰ تنتهي قريباً | الجميع | اشتراكات على وشك الانتهاء — فرصة تجديد |
| 🔎 بحث عن زبون | الجميع | بالاسم أو اليوزر أو الهاتف أو رمز الوثيقة |

## 3. الأوامر

```
/menu     القائمة            /stock    المخزون
/stats    مبيعاتك            /pending  عملياتك المعلّقة
/id       رقمك في تليجرام    /help     كل الأوامر
```

للمالك:

```
/admins                                  قائمة الأدمن
/addadmin  <رقم تليجرام> [الاسم]
/deladmin  <رقم تليجرام>
/addproduct  <رمز> <الاسم>               مثال: /addproduct netflix نتفليكس
/addvariant  <رمز المنتج> <رمز المدة> <الاسم>
/addcards    <رمز المنتج> <رمز المدة>    ثم الأكواد سطراً سطراً
/allstats                                مبيعات الجميع
/breakdown                               المبيعات حسب المنتج
```

شحن الأكواد في رسالة واحدة:

```
/addcards giftcard year
XXXX-1111-AAAA
XXXX-2222-BBBB
XXXX-3333-CCCC
```

الكود المكرّر داخل نفس المدة يُتجاهل ويُعدّ لك، فلصق نفس القائمة
مرتين لا يضاعف المخزون.

## 4. زيادة منتجات ومدد

لا هجرة ولا نشر. من داخل البوت:

```
/addproduct netflix نتفليكس
/addvariant netflix year    سنة
/addvariant netflix 6months 6 أشهر
/addcards   netflix year
NFX-0001
NFX-0002
```

يظهر المنتج فوراً في زر البيع لكل البائعين. و«جيفت كارد» بمدّتيها
(سنة / 3 أشهر) مزروعة أصلاً عند تطبيق الهجرة.

لإخفاء منتج أو مدة مؤقتاً دون فقدان مخزونها، استعمل زر المخزون —
البطاقات وسجل المبيعات يبقيان كما هما.

## 5. التركيب — مرة واحدة

### 5.1 أنشئ البوت

في تليجرام، راسل **@BotFather** ← `/newbot` ← اختر اسماً ومعرّفاً.
يعطيك توكن بهذا الشكل: `123456789:AAxxxxxxxxxxxxxxxxxxx`.

> إن كان لديك بوت الإشعارات الحالي (`TELEGRAM_BOT_TOKEN` الذي يستقبل
> الطلبات من المتجر) فالأفضل **بوت جديد منفصل** لهذا: هذا يستقبل
> أوامر ويعطي أكواداً، وذاك يرسل إشعارات فقط.

### 5.2 اعرف رقمك

راسل **@userinfobot** في تليجرام، يعطيك رقمك (`id`). هذا الرقم هو
مالك البوت. أو افتح البوت بعد نشره وأرسل `/id`.

### 5.3 اضبط الأسرار

```bash
supabase secrets set TELEGRAM_BOT_TOKEN=123456789:AAxxxxxxxxxxxxx
supabase secrets set TELEGRAM_OWNER_ID=YOUR_TELEGRAM_ID
supabase secrets set TELEGRAM_WEBHOOK_SECRET="$(openssl rand -hex 32)"
```

`TELEGRAM_WEBHOOK_SECRET` نص عشوائي تخترعه أنت. **بدونه لا يعمل
البوت إطلاقاً** — يردّ 503 على كل تحديث. السبب في §6.

> ⚠️ لا تستعمل `TELEGRAM_BOT_TOKEN` نفسه للبوتين إن أنشأت بوتاً
> جديداً؛ اضبط توكن بوت المخزون هنا، وسيستعمله `submit-order` أيضاً
> للإشعارات. إن أردت الفصل التام، أنشئ مشروعين أو غيّر اسم المتغيّر
> في إحدى الدالتين.

### 5.4 انشر الدالة

```bash
supabase functions deploy telegram-bot --no-verify-jwt
```

`--no-verify-jwt` ضرورية: تليجرام لا يعرف مفاتيح Supabase ولن يرسل
`Authorization`. ما يحرس الدالة هو الترويسة السرّية لا المفتاح.

من اللوحة بدل الطرفية: **Edge Functions → Deploy a new function**،
الاسم `telegram-bot` بالضبط، والصق `dist-functions/telegram-bot.ts`
(يُولَّد بـ `bash tools/build-functions.sh`)، ثم أطفئ **Verify JWT**.

### 5.5 اربط الـwebhook

```bash
curl -X POST "https://api.telegram.org/bot<TOKEN>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{
        "url": "https://<PROJECT-REF>.supabase.co/functions/v1/telegram-bot",
        "secret_token": "<نفس TELEGRAM_WEBHOOK_SECRET>",
        "allowed_updates": ["message","callback_query"]
      }'
```

للتأكد: `curl "https://api.telegram.org/bot<TOKEN>/getWebhookInfo"` —
يجب أن يظهر رابطك و `pending_update_count: 0` بلا `last_error_message`.

### 5.6 افتح البوت

أرسل `/start`. تُفتح لك القائمة كمالك تلقائياً لأن رقمك في
`TELEGRAM_OWNER_ID`. ثم:

```
/addcards giftcard year
... الأكواد ...
/addadmin 987654321 محمد
```

يرسل محمد `/start` فيجد قائمته جاهزة. (ليعرف رقمه: يفتح البوت
ويرسل `/id`، أو يراسل @userinfobot.)

## 5-ب. التركيب من الهاتف — بلا حاسوب إطلاقاً

ممكن بالكامل. كل ما تحتاجه: **متصفّح + تليجرام**. لا سطر أوامر ولا
`supabase` CLI ولا حتى ملف تنزّله.

> افتح المتصفّح في **وضع خاص/تصفّح متخفٍّ**. ستضع التوكن والسرّ في
> رابط، والروابط تُحفظ في سجلّ التصفّح.

**١. البوت والرقم** (تليجرام)

* **@BotFather** ← `/newbot` ← انسخ التوكن.
* **@userinfobot** ← انسخ رقمك.

**٢. اخترع السرّ**

أي نص عشوائي طويل (30 حرفاً فأكثر، حروف لاتينية وأرقام فقط، بلا
مسافات). اكتبه في **مفكّرة هاتفك** — ستلصقه مرتين ثم لن تحتاجه أبداً.

**٣. مشروع Supabase**

`supabase.com` ← Sign up ← New project. من رابط المشروع خذ الـ`ref`:
`supabase.com/dashboard/project/`**`xxxxxxxx`** ← هذا هو الـ`ref`.

**٤. القاعدة** — لصقة واحدة

افتح **`docs/bot-setup.sql`** في GitHub من هاتفك، واضغط زر **نسخ
الملف الخام** (أيقونة النسخ فوق الملف). ثم في Supabase:
**SQL Editor ← New query ← الصق ← Run**.

هذا الملف ~36 كيلوبايت ويكفي للبوت وحده. (`docs/full-setup.sql` هو
المتجر كاملاً، 228 كيلوبايت — لا تحتاجه إن أردت البوت فقط، وإن
كنت نشرت المتجر أصلاً فلصق هذا فوقه آمن ولا يمسّ شيئاً قائماً.)

**٥. الدالة** — لصقة ثانية

في Supabase: **Edge Functions ← Deploy a new function**، الاسم
`telegram-bot` بالضبط. الصق محتوى
**`supabase/functions/telegram-bot/index.ts`** (نفس زر النسخ الخام في
GitHub)، وقبل النشر **أطفئ خيار Verify JWT**.

> إن لم تجد محرّراً في لوحتك، فهذه الخطوة وحدها تحتاج حاسوباً أو
> ربط المستودع بـGitHub Integration. الباقي كله يعمل من الهاتف.

**٦. الأسرار**

في Supabase: **Edge Functions ← Secrets** (أو Project Settings ←
Edge Functions)، أضف ثلاثة:

| الاسم | القيمة |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توكن BotFather |
| `TELEGRAM_OWNER_ID` | رقمك من @userinfobot |
| `TELEGRAM_WEBHOOK_SECRET` | السرّ من خطوة ٢ |

**٧. اربط الـwebhook — من شريط العنوان**

تليجرام يقبل هذه الأوامر عبر رابط عادي، فلا حاجة لـ`curl`. عدّل
القيمتين والصق الرابط في المتصفّح:

```
https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<REF>.supabase.co/functions/v1/telegram-bot&secret_token=<السرّ>
```

الردّ الصحيح:

```json
{"ok":true,"result":true,"description":"Webhook was set"}
```

(لا حاجة لـ`allowed_updates` هنا: `message` و`callback_query` من
الأنواع الافتراضية التي يرسلها تليجرام أصلاً.)

للفحص لاحقاً — نفس الطريقة:

```
https://api.telegram.org/bot<TOKEN>/getWebhookInfo
```

يجب أن يظهر رابطك بلا `last_error_message`.

**٨. افتح البوت وأرسل `/start`**

تُفتح لك قائمة المالك. اشحن أكوادك وأضف بائعيك من داخل البوت — §3.

**بعدها لا حاجة للحاسوب أبداً**: الشحن، إضافة المنتجات والمدد،
إضافة البائعين وتعطيلهم، والتقارير — كلها من داخل البوت في هاتفك.

## 5-ج. لم يردّ البوت؟ شغّل الفاحص

```bash
bash tools/check-bot.sh
```

أشيع أعطال هذا النشر **لا تُنتج رسالة خطأ في أي مكان** — البوت
ببساطة يصمت. الفاحص يميّز بينها ويقول أيّها هو:

| ما يقوله | المعنى |
|---|---|
| ✅ الدالة منشورة والترويسة تحرسها | الدالة سليمة |
| ❌ Verify JWT ما زال مشتعلاً | نُشرت بلا `--no-verify-jwt` — تليجرام لا يمرّ منه أبداً |
| ❌ السرّ غير مضبوط | الدالة ترفض كل شيء بـ503 حتى تضبطه |
| ❌ لا توجد دالة بهذا الاسم | الاسم ليس `telegram-bot` بالضبط |
| ❌ لا يوجد webhook مربوط | نسيت خطوة `setWebhook` |
| ❌ مربوط على رابط آخر | يشير إلى مشروع/دالة غير هذه |
| ❌ السرّ يخالف الذي في Supabase | `setWebhook` بسرّ غير الذي في الأسرار |

وإن كان `TELEGRAM_WEBHOOK_SECRET` في `.env.deploy`، يمرّر رسالة `/id`
حقيقية في المسار كاملاً — الدالة ثم القاعدة ثم تليجرام — فتصلك رسالة
في هاتفك. وصلت؟ إذاً كل شيء يعمل.

> الفاحص لا يطبع التوكن ولا السرّ في أي حال.

**من الهاتف** بلا سطر أوامر، افتح هذا في المتصفّح:

```
https://api.telegram.org/bot<TOKEN>/getWebhookInfo
```

`"url"` فارغ = لا webhook. `last_error_message` موجود = تليجرام يصل
ويُرفض (غالباً السرّ مختلف). `pending_update_count` كبير = الدالة
ترفض ما يصلها.

## 5-د. من باع ماذا وكم

ثلاثة مستويات، كلها محسوبة من `bot_issues` لحظة القراءة — لا عدّاد
مخزّن يمكن أن يفارق السجل:

**البائع عن نفسه** — `/stats` أو زر 📊:

```
📊 مبيعاتك

✅ عمليات ناجحة: 12
📅 اليوم: 3
🗓 هذا الشهر: 12
❌ ملغاة: 2
⏳ معلّقة الآن: 0

ماذا بعت بالضبط:
• نتفليكس — سنة: 8
• نتفليكس — 3 أشهر: 3
• بطاقة جيفت كارد — سنة: 1
```

**المالك عن الجميع** — `/allstats` أو 🏆: نفس التفصيل تحت كل بائع،
مرتَّبين بالأكثر بيعاً.

**المالك عن بائع بعينه** — زر 👥 الأدمن ثم اضغط على اسمه.

المدد التي لم يبع منها شيئاً لا تظهر: قائمة أصفار ليست تقريراً. والمدة
التي طُلبت ثم أُلغيت لا تُحسب بيعاً، ويظهر عدد إلغاءاتها بجانبها.

## 5-هـ. وثيقة الضمان

بعد **✅ تأكيد**، يسأل البوت البائع عن بيانات الزبون، ثم يُصدر وثيقة
فيها متى بدأ الاشتراك ومتى ينتهي — والتاريخان محسوبان من مدة المدّة
نفسها، لا يكتبهما أحد بيده.

```
🧾 بيانات الزبون — 9d634e5c-…

ردّ على هذه الرسالة ببيانات الزبون، قيمة في كل سطر وبنفس الترتيب:

1. يوزر الأنستا
2. رقم الهاتف (اختياري)
```

يردّ البائع:

```
@ahmed_dz
0550111222
```

فتصدر فوراً:

```
🧾 وثيقة ضمان — Janeiro

متابعين انستا — سنة

👤 الزبون
يوزر الأنستا: @ahmed_dz
رقم الهاتف: 0550111222

📅 يبدأ: 2026-09-10
📅 ينتهي: 2027-09-10 (365 يوماً)

🔖 رمز التحقق: JNR-501D78C7AA784D
البائع: محمد
```

رسالة واحدة قائمة بذاتها — يعيد البائع توجيهها للزبون كما هي. لا
رابط ولا مرفق، فتعمل على أي هاتف.

### الحقول تُحدَّد لكل منتج

منتج يُفعَّل بيوزر أنستا، وآخر بيوزر سناب، وثالث يحتاج الاسم والهاتف:

```
/addfield insta يوزر الأنستا
/addfield snap  يوزر السناب
/addfield snap  الاسم
/addfield snap  رقم الهاتف optional
/fields                          ← ما هو مضبوط الآن
/delfield insta يوزر الأنستا
```

الحقل المطلوب لا يمكن تخطّيه: الإصدار يتوقف ويسمّي الحقل الناقص.
والاختياري يُتخطّى بسطر فارغ أو `-`.

**لا حقل لكلمة سر.** قاعدة البيانات ترفضه، مثل المتجر تماماً.

### المدة

الوثيقة تحتاج مدة محسوبة لتعرف متى تنتهي. «سنة» و«3 أشهر»
المزروعتان مضبوطتان. لأي مدة تضيفها بنفسك:

```sql
update bot_variants set duration_value = 6, duration_unit = 'month'
 where code = '6months';
```

(`day` / `week` / `month` / `year`.) بلا مدة تصدر الوثيقة بتاريخ
بداية فقط.

### بعد البيع

```
/cert JNR-501D78C7AA784D      الوثيقة كاملة بالرمز
/find ahmed                    ابحث بأي حقل: يوزر، اسم، رقم، أو رمز
/find 0550111222
/expiring        من ينتهي اشتراكه خلال 7 أيام
/expiring 30     أو 30
```

وزرّان في القائمة: **⏰ تنتهي قريباً** و**🔎 بحث عن زبون**.

البائع يرى وثائقه وزبائنه وحده؛ المالك يرى الجميع.

### ماذا يُخزَّن

| الجدول | ما فيه |
|---|---|
| `bot_fields` | أي بيانات يُسأل عنها لكل منتج |
| `bot_certificates` | الرمز، البيعة، بيانات الزبون، البداية والنهاية |

بيانات الزبون **لقطة** داخل الوثيقة: حذف حقل أو إعادة تسميته لاحقاً
لا يغيّر وثيقة صادرة. ووثيقة واحدة لكل بيعة — مفتاح فريد يضمنها، لا
فحص يسبقها. ولا تصدر لبيعة لم تُؤكَّد.

## 5-و. الزبون يعبّي بنفسه، ويحفظ وثيقته

بعد التأكيد يظهر للبائع خياران:

```
🧾 بقيت بيانات الزبون
المطلوب: الاسم · يوزر السناب · رقم الهاتف

┌──────────────────────────────┐
│ 🔗 يعبّيها الزبون بنفسه       │
├──────────────────────────────┤
│ ✍️ أكتبها أنا                 │
└──────────────────────────────┘
```

**🔗 يعبّيها الزبون** ينتج رابطاً يُرسَل في سناب أو واتساب. الزبون
يفتحه فيجد استمارة عربية على هاتفه، يكتب اسمه ويوزره ورقمه، ويضغط
**إصدار الوثيقة** — فتظهر له الوثيقة كاملة في نفس اللحظة:

* تاريخ بدء الاشتراك وتاريخ انتهائه
* رمز تحقّق يثبت اشتراكه في أي مراجعة
* زر **حفظ أو طباعة PDF**
* وأسفلها **كل قنوات تواصلكم** — سناب، تليجرام، الهاتف…

والبائع يصله إشعار في تليجرام أن زبونه عبّأ، بما كتبه.

رابط الاستمارة **يُستعمل مرة واحدة** وينتهي بعد أسبوع. أما رابط
الوثيقة نفسها فيبقى: يحفظه الزبون ويعود إليه متى شاء.

> الاستمارة والوثيقة **لا تعرضان كود البطاقة أبداً** — الزبون أخذه
> من البائع، ولا شأن لهاتين الصفحتين به. مضمون في الاختبارات.

**✍️ أكتبها أنا** يبقى متاحاً للبائع حين يكون الزبون أمامه. أول من
يعبّي يُصدر الوثيقة.

### قنوات التواصل أسفل الوثيقة

```
/addcontact سناب شات | janeiro_store | https://snapchat.com/add/janeiro_store
/addcontact تليجرام | @janeiro_support | https://t.me/janeiro_support
/addcontact الهاتف | 0550 11 22 33
/contacts        ← ما هو مضبوط
/delcontact سناب شات
```

الأجزاء مفصولة بـ `|` لأن التسميات عربية وفيها مسافات. الرابط
اختياري — بوجوده يصير السطر قابلاً للضغط. ونفس التسمية تُحدَّث ولا
تتكرّر، فتغيير رقمك لا يترك القديم معروضاً.

### «من ينتهي اشتراكه اليوم؟»

زر **⏰ تنتهي قريباً** ثم **اليوم** — أو `/expiring 0`. وبقية المدد
7 و30 و90 يوماً.

هذه قائمة تجديد: تعرف من تكلّم قبل أن ينتهي اشتراكه، وتجد رقمه
ويوزره في نفس السطر.

### الوصول لأي زبون

```
/find ahmed          بالاسم أو اليوزر
/find 0550112233     بالرقم
/find JNR-4E21…      برمز الوثيقة
```

كل ما عبّأه أي زبون محفوظ في `bot_certificates.customer` — لا يضيع،
ولا يتغيّر إن أعدت تسمية الحقول لاحقاً.

## 6. الأمان

**من ليس في جدول `bot_admins` لا يرى شيئاً.** أي شخص يفتح البوت
يُردّ برسالة واحدة فيها رقمه ليعطيه لك، ولا شيء غير ذلك: لا مخزون
ولا أسماء منتجات ولا وجود عمليات.

**الترويسة السرّية هي كل الحماية.** الدالة منشورة بلا تحقق من JWT،
فأي أحد يعرف رابطها يستطيع إرسال تحديث مزوّر يدّعي فيه أنه أدمن
ويفرّغ المخزون. لذلك:

* تليجرام يرسل `X-Telegram-Bot-Api-Secret-Token` مع كل تحديث، والدالة
  ترفض بـ401 كل ما لا يطابقه.
* وإن لم يُضبط السر أصلاً، ترفض **كل شيء** بـ503 بدل أن تعمل مكشوفة.

**قاعدة البيانات مغلقة بدورها.** جداول البوت الخمسة عليها RLS بلا أي
policy، ولا `anon` ولا `authenticated` يملك صلاحية عليها ولا على أي
دالة `bot_*`. الطريق الوحيد هو `service_role` من داخل الدالة. أي
تسريب للـanon key لا يفتح المخزون.

**الكود يُمحى عند الإلغاء.** البطاقة الملغاة ترجع للتداول وقد تُسلَّم
لزبون آخر، فلا تبقى معروضة في محادثة قديمة.

## 7. جداول قاعدة البيانات

| الجدول | ما فيه |
|---|---|
| `bot_admins` | من يدخل البوت، ودوره (`owner` / `admin`) |
| `bot_products` | المنتجات — قابلة للزيادة من البوت |
| `bot_variants` | المدد داخل كل منتج (سنة، 3 أشهر، …) |
| `bot_cards` | الأكواد وحالتها: `available` / `reserved` / `sold` |
| `bot_issues` | سجل كل طلب: من طلبه، متى، وماذا صار له |

عدّاد المبيعات ليس عموداً يُزاد يدوياً — يُحسب في كل مرة من
`bot_issues`. فلا يمكن أن يقول العدّاد شيئاً ويقول السجل غيره.

الاسم المعروض للبائع: ما سمّيته به أنت عند إضافته، فإن لم تسمّه
فاسمه في تليجرام. اسمه في تليجرام يُحدَّث مع كل رسالة لكنه **لا
يمحو** تسميتك.

## 8. أسئلة تتكرر

**بائع ضغط «تأكيد» بالخطأ.** التأكيد نهائي. البطاقة مباعة والعملية
محسوبة. تُصلَح من قاعدة البيانات مباشرة (`bot_issues` و`bot_cards`)،
وليس من البوت — عمداً، حتى لا يستطيع بائع محو عملية بعد إغلاقها.

**بائع لم يضغط شيئاً وترك البطاقة معلّقة.** تبقى محجوزة، وتراها في
**⏳ المعلّقة**، وتستطيع أنت (كمالك) إغلاقها بالإلغاء فترجع للمخزون.
ولا تُطلق تلقائياً بعد مهلة: الكود قد يكون سُلّم للزبون فعلاً،
وإرجاعه للمخزون بلا قرار إنسان يبيعه مرتين.

**بائع يحجز كثيراً بلا بتّ.** هناك سقف للعمليات المعلّقة للبائع
الواحد (5 افتراضياً). لتغييره:

```sql
update store_settings set value = '10' where key = 'bot_pending_limit';
```

**حذفتُ بائعاً، ماذا يحصل لمبيعاته؟** تبقى منسوبة إليه في التقارير.
لا يُحذف الصف، بل يُعطَّل، وبطاقاته المعلّقة ترجع للمخزون فوراً.

**هل يستعمله الزبون؟** لا. الزبون في المتجر، والبوت للأدمن.

## 9. الاختبار محلياً

```bash
bash tests/local/run-tests.sh
```

يشغّل ثلاثة اختبارات للبوت:

| الملف | ما يثبته |
|---|---|
| `tests/bot.test.sql` | منطق الحجز والتأكيد والإلغاء والصلاحيات والعدّاد |
| `tests/local/bot-concurrency.test.sh` | باتصالات متوازية حقيقية: لا كود يخرج لبائعين، ولا تأكيدان لعملية |
| `tests/local/bot-e2e.test.js` | الدالة نفسها تعمل على Deno، وتُقرأ الرسائل والأزرار التي أرسلتها فعلاً |

الأخير يحتاج **deno** مثبّتاً؛ بدونه يتخطّى نفسه برسالة واضحة ولا
يُفشل التشغيل. ويستعمل المنفذ 8000 لأن `Deno.serve()` لا يقبل غيره
بلا خيارات.
